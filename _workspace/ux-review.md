# 현재 화면 UX 검토

대상: dev 서버(`127.0.0.1:8081`)의 `/`, `/programs`, `/sites`, `/runs/1`과 템플릿 5개, `app/main.py`, `app/doctor.py`.
사용자는 한 명이고, 가끔 열어서 세 가지 일을 한다.

- A. 크롤링이 정상인지, 무엇이 받아졌는지 확인한다
- B. 따라갈 프로그램을 추가하거나 지운다
- C. 고장난 사이트를 고친다(doctor 실행, 제안 적용)

원칙은 "가장 작은 변경"이다. JS 프레임워크를 쓰지 않는다. htmx는 이미 쓰는 doctor 화면에만 둔다. 나머지는 Jinja 필터와 CSS, 네이티브 기능(`confirm()`, `<time>`, `aria-current`)으로 해결한다.

조사 시점의 dev DB: 실행 1건(#1, `error`, 19:23:10~19:35:40, 로그는 `interrupted by restart` 한 줄), 다운로드 0건, doctor 리포트 0건, 프로그램 17개, 사이트 5곳.

## P1 반드시 고친다

### P1-1. 대시보드에서 "지금 괜찮은가"가 2초 안에 보이지 않는다 (A)
- **문제**: 상단에는 `다음 실행: 2026-10-18 20:23`만 있다. 마지막 실행의 결과는 표의 첫 행, 네 번째 칸에 있는 작은 배지로만 보인다. 다음 실행은 절대 시각이라 "언제쯤인지"를 사용자가 직접 계산해야 한다.
- **근거**: `index.html` 7~10행. 지금 dev 화면은 마지막 실행이 `error`인데 상단에는 아무 신호가 없다.
- **제안**: `<h1>` 바로 아래에 한 줄 요약을 둔다. 데이터는 이미 넘어오는 `runs[0]`으로 충분하다.
  ```
  [실패] 마지막 실행 #1 · 19:23 (1시간 전) · 매칭 0 · 추가 0 · 로그 보기
  다음 실행 20:23 (42분 후) · 60분마다
  ```
  - 상대 시각은 서버에서 계산하는 Jinja 필터 `ago(dt)` 하나로 만든다("방금", "N분 전/후", "N시간 전/후"). JS는 쓰지 않는다. 페이지를 열 때의 값이면 충분하다.
  - 마지막 실행이 `error`나 `partial`이면 요약 줄 끝에 `사이트 확인 →`(`/sites`) 링크를 붙인다. 고장 확인(A)에서 수리(C)로 바로 넘어가게 하기 위해서다.
  - `next_run_at`이 과거인데 실행 중이 아니면(Mac이 잠자고 깨어난 직후) "곧 실행"으로 표시한다.

### P1-2. 되돌릴 수 없는 동작과 돈이 드는 동작에 확인 단계가 없다 (B, C)
- **문제**: 프로그램 [삭제]는 한 번 누르면 바로 지워진다. [끄기] 버튼과 크기도 모양도 같고, 바로 옆 칸에 있다. 사이트 [doctor]는 누를 때마다 최대 $1이 든다. doctor 리포트의 [적용]과 사이트 [수정 → 적용]은 크롤링 대상 URL을 바꾼다.
- **근거**: `programs.html` 27행, `sites.html` 37~43행, `doctor.html` 25~30행. 모두 확인 없이 POST한다.
- **제안**: 각 `<form>`에 네이티브 `onsubmit="return confirm(...)"`를 붙인다.
  - 삭제: `confirm('「{{ p.name }}」을 삭제할까요? 다운로드 기록은 남습니다.')` (`ON DELETE SET NULL`이므로 기록이 남는 것이 맞다)
  - doctor: `confirm('{{ s.name }} 진단을 시작할까요? 최대 $1이 듭니다.')`
  - 리포트 적용: `confirm('사이트 URL을 {{ fix.url }}로 바꿀까요?')`
  - 사이트 수정: 같은 패턴을 쓴다. `<details>`를 열고 다시 [적용]을 눌러야 하므로 우선순위는 가장 낮다.
  - 삭제 버튼에 `.danger` 스타일을 주고, [끄기]와 다른 칸에 떨어뜨려 둔다(P2-6 참고).

### P1-3. 오류가 JSON 원문이나 영어로 나온다 (B, C)
- **문제**: 입력 오류와 404가 FastAPI 기본 JSON으로 나온다. 앱의 오류 메시지도 영어다.
- **근거**:
  - `/runs/999` → `{"detail":"run not found"}`
  - 주기에 0을 POST하면 → `{"detail":[{"type":"greater_than_equal",...}]}`. 브라우저의 min/max가 대부분 막아 주지만 우회할 수 있다.
  - doctor [적용]에서 검증이 실패하면 `HTTPException(400)`이 JSON으로 나온다(`doctor.py` 292, 300행).
  - flash 메시지는 `duplicate name: 라디오스타`, `bad url`, `bad board: ...`, `boards empty`처럼 영어다(`db.py` 105~153행).
- **제안**:
  - `db.py`의 `ValueError` 메시지를 한국어로 바꾼다: `이미 있는 이름입니다: 라디오스타`, `URL 형식이 잘못됐습니다`, `게시판 경로가 잘못됐습니다: ...`, `게시판을 하나 이상 입력하세요`. 테스트가 메시지 문자열을 확인하고 있다면 테스트도 같이 고친다.
  - `apply_fix`의 검증 실패는 `main.go("/sites", str(e))`처럼 redirect와 flash로 돌린다. 이미 있는 패턴을 그대로 쓰는 것이다.
  - 404와 422는 `main.py`에 `@app.exception_handler(HTTPException)` 하나를 두고, `base.html`을 상속한 짧은 오류 페이지(메시지와 `← 대시보드` 링크)를 렌더한다. 템플릿 하나, 함수 하나면 된다.

### P1-4. POST 뒤에 무슨 일이 일어났는지 알려 주지 않는다 (A, C)
- **문제**: [지금 실행]을 누르면 `/`로 돌아올 뿐 아무 표시가 없다. 스케줄러가 깨어나서 lock을 잡기 전에 응답이 오므로 `실행 중` 배지도 대부분 뜨지 않는다(`trigger_now`는 이벤트만 세운다). 실행 중에는 페이지가 갱신되지 않아서, 끝났는지 보려면 사용자가 직접 새로고침해야 한다. doctor [적용] 뒤에도 `/sites`로 조용히 돌아간다.
- **근거**: `main.py` 59~61행. flash는 `already-running` 하나뿐이다. `doctor.py` 302행.
- **제안**:
  - `run_now`가 성공하면 `/?msg=started`로 보내고 `실행을 시작했습니다.` flash를 띄운다.
  - `running`이거나 `msg == "started"`이면 `{% block head %}<meta http-equiv="refresh" content="10">{% endblock %}`을 넣는다. 끝나면 자동 갱신도 멈춘다. 네이티브 기능 한 줄이다.
  - `apply_fix`는 `/sites?msg=applied`로 보내고 `{{ site.name }} 설정을 바꿨습니다. 다음 실행에서 확인됩니다.`를 띄운다. 가능하면 [지금 실행] 버튼을 같이 둔다.
  - 프로그램 추가, 삭제, 켜기/끄기는 표에 결과가 바로 보이므로 flash가 필요 없다.

## P2 고치는 게 좋다

### P2-1. 날짜가 ISO 원문(`2026-10-18T19:23:10`)으로 나온다 (전체)
- **근거**: 대시보드의 시작·종료·추가 시각, 실행 상세, doctor의 `시작`, 사이트의 `최근 성공`. 대시보드의 `다음 실행`만 `strftime`을 거친다. 같은 화면 안에서 형식이 두 가지다.
- **제안**: Jinja 필터 `dt` 하나로 `<time datetime="{{ v }}" title="{{ v }}">10-18 19:23</time>`을 출력한다. 올해이면 연도를 빼고, 오늘이면 `19:23`만 쓴다. 정확한 값은 `title`로 볼 수 있다. P1-1의 `ago`와 같은 파일에 둔다.
- 최근 실행 표의 `종료` 칸은 `소요`(예: `12분 30초`)로 바꾼다. 종료 시각보다 "오래 걸렸나"가 더 쓸모 있다. 실행 중이면 `실행 중`이라고 쓴다.

### P2-2. 상태 배지가 한국어 화면 속 영어 원시값이다 (전체)
- **주장**: 한국어 라벨로 바꾸고, 원시값은 `title`에 남긴다. 이 사용자는 가끔 열어서 2초 안에 판단하려 한다. `partial`과 `parser_broken`은 읽는 데 번역 단계가 하나 더 필요하다. 원시값은 로그와 README 표에서 찾아볼 때 필요하므로, 툴팁과 CSS 클래스로 남긴다.
- **제안**: `main.py`에서 `templates.env.globals["LABEL"]`에 dict 하나를 넣는다(doctor 템플릿도 같은 env를 쓴다).

  | 원시값 | 라벨 |
  |---|---|
  | ok | 정상 |
  | partial | 일부 실패 |
  | error | 실패 |
  | running | 실행 중 |
  | done | 완료 |
  | domain_moved | 도메인 이전 |
  | blocked | 차단 |
  | site_down | 사이트 다운 |
  | cloudflare | CF 인증 필요 |
  | parser_broken | 파서 고장 |

  `<span class="badge {{ s }}" title="{{ s }}">{{ LABEL.get(s, s) }}</span>`처럼 쓴다. 배지를 그리는 곳이 4군데이므로 `{% macro badge(s) %}`로 묶는다. 이렇게 하면 색과 글자가 함께 상태를 전하므로 색에만 의존하지도 않는다.
- `해상도`의 `any`도 화면에서는 `무관`으로 보인다(value는 그대로 둔다). README의 화면 설명도 이미 "무관"이라고 쓰고 있다.

### P2-3. DEV 배지가 `partial` 배지와 같은 색이다 (A)
- **근거**: `base.html` 43행이 `class="badge partial"`을 쓴다. 노란 "일부 실패" 배지와 모양이 같고, 크기 12px로 nav 끝에 붙어 있다.
- **제안**: `.env-dev` 클래스를 따로 만든다(보라 계열이나 줄무늬 배경 등 상태 색과 겹치지 않는 색). dev에서는 대시보드 요약 줄 앞에 `dry-run: Transmission 추가와 다운로드 기록, URL 변경, 최근 성공 갱신을 하지 않습니다.`를 muted로 한 줄 넣는다. 지금은 이 설명이 배지의 `title`에만 있어서 마우스를 올려야 보이고, 모바일에서는 볼 방법이 없다.
- dev에서는 다운로드 이력이 항상 비고 `최근 성공`이 항상 `-`이다. 빈 상태 문구를 `아직 없음 (dev는 기록하지 않음)`으로 바꾼다.

### P2-4. 사이트의 켜짐/꺼짐 상태가 버튼 글자로만 보인다 (C)
- **근거**: `sites.html`의 `상태` 칸에는 [끄기] 버튼만 있다. 프로그램 화면은 `[끄기] 켜짐`처럼 상태 글자를 같이 쓴다. 같은 동작인데 두 화면의 표현이 다르다. "끄기"라는 동사는 지금 상태가 아니라 누르면 일어날 일이라서, 상태를 거꾸로 읽게 된다.
- **제안**: 두 화면 모두 `켜짐 [끄기]` 순서로 맞춘다. 상태가 먼저, 동작이 뒤다. 꺼진 행의 흐린 색(`tr.off`)은 그대로 둔다.

### P2-5. 사이트 행마다 있는 모델 선택이 전역 기본값과 중복된다 (C)
- **근거**: 상단의 `doctor 기본 모델 [sonnet] [적용]`과 각 행의 `[sonnet▾] [doctor]`. 행의 select는 늘 기본값으로 초기화되므로, 기본값 설정은 "행 select의 초기값"이라는 역할밖에 하지 않는다. 좁은 화면에서는 표가 넘친다(390px에서 표 365px > 본문 358px).
- **제안**: 행의 select를 지운다. `start_doctor`의 `model`을 `Form(None)`으로 받고, 값이 없으면 설정값을 쓴다. 가끔 opus로 돌리고 싶으면 상단 설정을 바꾼다. 사용자가 한 명이니 충분하다. 행에는 `[진단]` 버튼 하나만 남긴다.
- 버튼 문구 `doctor`는 `진단`으로 바꾼다. 화면 이름 "Doctor"는 README 용어이므로 h1에는 그대로 둔다.

### P2-6. 버튼 위계가 없다. 모든 버튼이 같은 회색 기본 버튼이다 (전체)
- **근거**: `적용`이 4곳(주기, 기본 모델, 사이트 수정, doctor 적용)에 있고, `지금 실행`, `추가`, `삭제`, `끄기`가 모두 같은 모양이다.
- **제안**: CSS 두 줄을 추가한다.
  - `.primary`(채운 파랑): `지금 실행`, `추가`, doctor `적용`
  - `.danger`(빨간 글씨와 테두리): `삭제`
  - 문구는 동작이 드러나게 바꾼다. 주기 `적용` → `저장`, 기본 모델 `적용` → `저장`, 사이트 수정 `적용` → `저장`. doctor 리포트의 `적용`은 사이트를 바꾸는 행동이므로 `이 설정으로 변경`으로 쓴다.

### P2-7. doctor 리포트: 적용할 내용이 현재 설정과 나란히 비교되지 않는다 (C)
- **근거**: 현재 설정은 상단에 muted 한 줄(`현재 설정: url boards`)로 있고, 제안은 아래 `수정 제안`에 따로 있다. 진행 로그 `<pre>`가 길면 둘 사이가 한 화면 넘게 벌어진다. 비용은 실행 중에 `-`로만 나온다.
- **제안**:
  - `수정 제안`을 2행 표로 만든다. `| | 현재 | 제안 |`에 url과 boards를 넣고, 값이 다른 칸은 `<strong>`으로 강조한다.
  - 진행 로그는 리포트가 끝나면 `<details><summary>진행 로그</summary>`로 접는다. 실행 중에는 펼쳐 두어 htmx 폴링이 보이게 한다.
  - 실행 중이면 비용 자리에 `진행 중 · 상한 $1`을 쓴다.
  - 요약과 판정을 화면 맨 위로 올린다(판정 배지 → 요약 → 비교 표 → 근거 → 로그 순서).

### P2-8. 사이트 화면의 "최근 성공"과 판정 배지에 시간 맥락이 없다 (C)
- **근거**: `최근 성공`이 ISO 원문이거나 `-`이다. 판정 배지가 언제의 진단인지 알 수 없다(리포트 `started`는 이미 있다).
- **제안**: `최근 성공`은 `ago` 필터로 쓰고(`3시간 전`), 기준(예: 켜진 사이트이고 주기의 3배 이상 지남)을 넘으면 `.badge.error`로 표시한다. 판정 배지 옆에는 `· 2일 전`을 muted로 붙인다. 오래된 `정상` 판정이 지금도 정상이라고 오해하지 않게 하기 위해서다.

### P2-9. 명암비가 낮다 (전체, 접근성)
- **근거**(측정값): `.muted` #888/흰 배경 = **3.54:1**, `tr.off td` #999 = **2.85:1**. 둘 다 WCAG AA의 작은 글씨 기준 4.5:1에 못 미친다. 배지 색(partial 5.29:1, error 6.52:1)은 통과한다.
- **제안**: `.muted { color: #666 }`(5.74:1), `tr.off td { color: #767676 }`(4.54:1).

### P2-10. 입력 라벨이 없다 (B, 접근성)
- **근거**: 프로그램 추가 폼의 이름 입력은 `placeholder="프로그램 이름"`만 있고 `<label>`이 없다. 해상도 select도 라벨이 없다. 사이트 수정의 url input과 boards textarea도 라벨이 없다(`boards`가 한 줄에 하나라는 안내도 없다).
- **제안**: 주기 입력처럼 `<label>이름 <input ...></label>`로 감싼다. textarea는 `<label>게시판 경로 (한 줄에 하나)`로 감싼다. placeholder는 예시로 바꾼다(`예: 놀면 뭐하니`).

## P3 하면 좋다

- **현재 페이지 표시 없음** (nav): 3개 링크가 늘 같은 모양이다. `base.html`에서 `request.url.path`로 `aria-current="page"`를 넣고, CSS `nav a[aria-current] { border-bottom: 2px solid }`를 준다. `/runs/*`는 대시보드에, `/doctor/*`는 사이트에 묶는다.
- **숫자 정렬**: `#`, `매칭`, `추가` 칸에 `class="num"`을 주고 `text-align: right; font-variant-numeric: tabular-nums`를 적용한다. `추가 > 0`인 셀은 굵게 해서 "받은 게 있다"가 눈에 띄게 한다.
- **긴 제목과 URL**: 토렌트 제목과 사이트 URL은 공백 없이 길어서 좁은 화면에서 표를 밀어낸다. `td { overflow-wrap: anywhere }` 한 줄을 넣는다. 표를 `<div style="overflow-x:auto">`로 감싸는 것은 그래도 넘칠 때만 한다.
- **다운로드 이력 칸**: 좁은 화면에서는 `사이트` 칸이 가장 덜 중요하다. `@media (max-width: 480px)`에서 `.hide-sm { display:none }`을 쓴다. 칸 순서는 `추가 시각 · 프로그램 · 회차 · 제목`이 좋다(최신 확인이 목적이므로 시각을 먼저 둔다).
- **프로그램 목록**: 17개 중 켜진 2개가 섞여 있다. 정렬 순서가 매칭 우선순위이므로(README "첫 번째가 이긴다") 순서는 바꾸지 않는다. 표 위에 `켜짐 2 / 전체 17`을 쓰고 `#` 칸 머리를 `순서`로 바꿔 의미를 알려 준다.
- **실행 상세 로그**: `<pre>`로 충분하다. 다만 `FAIL`, `ERROR`가 든 줄을 서버에서 `<mark>`로 감싸면 로그를 훑기가 빨라진다(Jinja에서 줄 단위로 처리). 대시보드 표를 다시 보지 않아도 되게 상단에 `← 대시보드`를 하나 더 둔다.
- **`interrupted by restart`가 `실패`로 보인다**: 재시작으로 끊긴 실행은 사이트 고장이 아니다. 라벨 매핑에서 따로 구분하려면 상태값이 필요하므로, 지금은 로그 첫 줄을 요약 줄에 보여 주는 정도로 둔다.
- **doctor 화면 뒤로 가기**: `← 사이트` 링크가 로그 아래 맨 끝에만 있다. h1 위에 하나 더 둔다.
- **포커스 표시**: 브라우저 기본 포커스 링은 살아 있다(`outline`을 지운 CSS가 없다). 버튼에 스타일을 입힐 때(P2-6) `:focus-visible { outline: 2px solid #0b5cad; outline-offset: 2px }`를 같이 넣어 기본 링이 사라지지 않게 한다.
- **링크 vs 버튼**: 상태를 바꾸는 것은 모두 `<form method=post>`의 `<button>`이고 이동은 모두 `<a>`이다. 올바르다. 다만 사이트 URL 링크는 새 탭으로 열리는 편이 낫다(`target="_blank" rel="noreferrer"`).

## 바꾸지 않는다

- **plain HTML 폼과 POST → 303 redirect(PRG)**: 새로고침해도 다시 전송되지 않는다. JS 없이 모든 동작이 된다.
- **htmx는 doctor 진행 폴링에만 쓴다**: 끝나면 `HX-Refresh`로 전체를 다시 그리는 방식은 단순하고 정확하다. 다른 화면으로 넓히지 않는다(대시보드 갱신은 `<meta refresh>`로 충분하다).
- **`<input type=number min=1 max=1440 required>`**: 서버 검증과 같은 범위를 쓴다.
- **사이트 수정의 `<details>` 인라인 편집**: 드물게 하는 작업을 접어 두는 데 맞는 도구다. textarea 높이를 게시판 수에 맞추는 것도 좋다.
- **탭 제목의 `[dev]` 접두어**와 nav의 DEV 배지가 있다는 것 자체(색만 바꾼다, P2-3).
- **배지에 글자가 있다**: 색만으로 상태를 전하지 않는다.
- **꺼진 행을 흐리게 하는 `tr.off`**(색 값만 조정한다, P2-9).
- **한 열짜리 960px 레이아웃과 viewport meta**: 390px에서도 가로 스크롤 없이 렌더된다(측정: 모든 페이지 `scrollWidth == 390`).
- **doctor 제안을 자동 반영하지 않고 [적용]을 누르게 한 것**: 확인 단계만 더한다(P1-2).
- **화면 3개 + 상세 2개 구성**: 세 가지 일에 정확히 대응한다. 화면을 더 만들지 않는다.
